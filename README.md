# Лабораторная: ps (polling) против bpftrace (eBPF)

## Часть 1. Bash + ps

Скрипт [`ps_count.sh`](ps_count.sh) в цикле вызывает `ps`, отбрасывает ядерные потоки
(их команда выводится в квадратных скобках `[имя]`) и собственные вызовы `ps`, а затем
считает уникальные PID, которые появились за время работы (по умолчанию 10 секунд).

```bash
chmod +x ps_count.sh
./ps_count.sh 10
```

## Часть 2. bpftrace

Каждый запуск новой программы проходит через системный вызов `execve`, поэтому считаем
срабатывания точки трассировки `tracepoint:syscalls:sys_enter_execve` и выходим через 10 секунд:

```bash
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_execve /comm != "ps_count.sh"/ { @execve = count(); } interval:s:10 { exit(); }'
```

Фильтр `/comm != "ps_count.sh"/` исключает вызовы `ps` и `awk`, которые запускает сам
скрипт из Части 1. Скрипт сам их тоже не считает, поэтому сравнение получается честным.

## Часть 3. Сравнение

Нагрузка с короткоживущими процессами (в отдельном терминале):

```bash
while true; do ls >/dev/null; ls >/dev/null; sleep 0.01; done
```

Запуск обоих замеров одновременно:

```bash
sudo -v
./ps_count.sh 10 & sudo bpftrace -e 'tracepoint:syscalls:sys_enter_execve /comm != "ps_count.sh"/ { @execve = count(); } interval:s:10 { exit(); }'; wait
```

Результаты (Linux 6.10, bpftrace v0.20.2):

```
Attaching 2 probes...
ps увидел новых процессов за 10 с: 785
@execve: 2386
```

| Инструмент | Процессов за 10 с |
|------------|-------------------|
| ps         | 785               |
| bpftrace   | 2386              |

Расхождение: (2386 − 785) / 2386 × 100% ≈ 67% процессов `ps` не увидел.

## Вывод

`bpftrace` зафиксировал заметно больше процессов, чем `ps`. Дело в том, что `ps`
работает по принципу поллинга: он делает снимок `/proc` в отдельные моменты времени.
Процесс, который родился и завершился между двумя снимками, в выводе не появляется
ни разу. `bpftrace` подключает eBPF-программу к точке трассировки в ядре, и она
срабатывает при каждом вызове `execve` в момент самого события. Поэтому ни один
запуск не пропускается, каким бы коротким ни был процесс.
